# Pre-send check

Run on every correspondence draft after the review loop and before the user sees it. Run it on the final text, after the last reviewer change. Confirm each item. Name any item the draft does not meet. Never hand the user a draft as finished while one is unmet. Say which one is missing and why, or ask for what is needed to fix it.

1. Thanks for something specific, not "thanks for the time." (Outreach: the "why" names something specific about the company instead.)
2. Reacts to something the person actually said or sent.
3. States plainly what the user wants or what interests them.
4. Has its own warm closing line.
5. Every fact about the user's background is verified against `profile.md` or the master resume.
6. Correct mode for what is being produced (correspondence for anything addressed to a person).
7. The final text, after every reviewer change, still meets hard rules 1 to 12 in `hard-rules.md`.
8. Nothing from the profile's Constraints, no backchannel detail, no pay figures, and no one else's contact details or private remarks from the company README Notes.

By default, show one line: "All 8 checks met," or name each unmet item and why. Show all eight lines only when the user asks.

If the draft is a cover letter, item 1 becomes "names the specific thing about the role that interests the user" and item 5 includes the roster pass.
